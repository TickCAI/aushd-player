> 参照对象：Infuse / VidHub / SenPlayer（苹果端媒体播放器的交互范式）

## 一、核心判断（论证）

### 1.1 为什么"全面重写 UI"是正确决策，而不是修补

上游 Zerk Play 的 UI 是 **10-foot TV 范式**（Kodi 血统）：焦点框导航、屏幕软键盘、D-pad 滚动箭头、左侧 rail + 横向海报行。它没有响应式断点、没有触屏手势、没有手机竖版——**修补它比重写它更贵**，因为它的导航模型（焦点框）与现代触屏模型（命中目标 + 手势）是互斥的，硬塞两套只会得到一个四不像。

### 1.2 为什么重写是可行的：分层架构审计结论

对现有代码做了结构审计，`lib/` 分为四层：

| 层 | 目录 | 重写波及 | 说明 |
|---|---|---|---|
| 数据/客户端层 | `lib/data/`（Emby/Jellyfin/TMDB 客户端） | **零波及** | 纯逻辑，与 UI 无关。`catalog_api.views()` 已核实存在（catalog_api.dart:51），智能加载库直接复用 |
| 播放核心层 | `lib/playback/`（mpv + media3 双后端、HDR 防护、字幕、音轨、trickplay、转码） | **小波及（评审修正）** | ⚠️ 研发评审发现：`mpv_backend.dart`/`media3_backend.dart` 反向 import `player_osd.dart` 并在播放层内部 push OSD 路由（mpv_backend.dart:96-98、media3_backend.dart:87-89）；`media3/osd_model.dart` 携带纯展示状态。重写 OSD 前必须先做**播放路由解耦**（把 route push 所有权反转到 UI 侧注入回调），OsdModel 允许迁移。HDR/字幕/音轨/转码逻辑本体不动 |
| 应用层 | `lib/app/`（release/hub_link/app_settings）+ `lib/services/`（updater/janus/remote） | **零波及** | v1.0.1 的 HDR 修复、更新器、hub 全部保留 |
| UI 层 | `lib/ui/`（77 个 Dart 文件、**约 1.8 万行**，评审修正——原估 1.1 万低估约 6 成；player_osd.dart 单文件 1546 行） | **全部重写** | 本次工程范围 |

**结论：重写只动 `lib/ui/`（约 1.1 万行 Dart），底层 100% 保留。** 以下资产原样继承：

- 中文 697 条 l10n（新 UI 复用同一套 key，语义不变则译文不变）
- DisplayGuard 崩溃安全 HDR 恢复（v1.0.1 修复）
- 自建更新器 + hub 兑换码 + 零依赖后端 + GitHub Actions 三平台 CI
- mpv（桌面）/ Media3（安卓）双播放后端与全部播放能力（HDR、音轨、字幕样式、trickplay 预览条）

### 1.3 Flutter 能力论证（三端一套代码是否现实）

| 疑问 | 结论 |
|---|---|
| 手机/桌面/TV 能共用一套 Widget 吗？ | 不能直接共用，但能共用**一套设计系统 + 页面逻辑**。做法：`AdaptiveShell` 按断点/设备形态选壳（底部 Tab / 侧栏 / 顶部 rail），页面内容组件做 adaptive 变体（如 `PosterCard.compact` vs `.hero`） |
| TV 焦点导航要重写吗？ | 不用从零写。`lib/ui/focus/` 的 FocusZone/TVFocusable 概念正确，只是视觉烂。重写为苹果 TV 风格（聚焦放大 + 圆角 + 抛光阴影），机制保留 |
| 手机竖版播放器靠什么？ | Media3 已就位（Android 原生硬解），OSD 重写为 iOS 风触控层（上滑面板、双指缩放未用、单击显隐） |

### 1.4 参照对象拆解（我们要抄的到底是什么）

| 参照 | 借鉴点 |
|---|---|
| **Infuse** | 首页"继续观看 + 最近添加"大卡流；详情页海报沉浸背景 + 磨砂信息卡；全局暗色高级感 |
| **VidHub** | 底部 Tab + 大海报墙（2 列竖版网格）；剧集/集数的清晰层级；播放器 OSD 的分体式按钮布局 |
| **SenPlayer** | 播放器本身的极简 OSD（单击显隐、圆角胶囊按钮、下滑关闭）；手势亮度/音量/进度 |

统一后的气质关键词：**海报优先（Poster-first）、深色材质（Dark Material）、大圆角（16–20px）、克制留白、无焦点框（TV 除外）、沉浸式转场**。

## 二、设计系统（Design Tokens）——全端唯一

### 2.0 主题策略：小清新浅色为默认（VidHub 范式 + AusHD 品牌色）

**色彩来源**：AusHD logo 渐变 `#DDEB86（青柠）→ #9BDFAC（薄荷绿）→ #5CD5C4（湖水青）→ #0CBDE6（天青蓝）`，字标近黑 `#212228`。整套 UI 从 logo 取色，不是贴色。

**双模式原则**（对齐 VidHub "浅色/深色/跟随系统"三态，已核实）：

| 场景 | 模式 | 理由 |
|---|---|---|
| 浏览层（首页/媒体库/详情/搜索/设置） | **浅色小清新（默认）** | VidHub 同款气质：白底、大留白、薄荷青渐变点缀，海报彩色在浅底上更"鲜" |
| 播放层（播放器 OSD 内） | **沉浸深色** | 看片场景刚需，OSD 磨砂深色浮在视频上，不受主题影响 |
| TV 端 | **深色** | 客厅大屏环境光弱，浅色刺眼；TV 保留深色 + 品牌渐变点缀 |
| 深色主题（浏览层） | 跟随系统自动切换（v2.0 提供简版） | 夜间自动转暗，非重点打磨 |

### 2.1 色彩

**浅色（默认·浏览层）**

```
页面基底        bg.base        #F6F9F8   (近白，带一丝薄荷灰)
表面一级        bg.surface     #FFFFFF   (卡片)
表面二级        bg.subtle      #EEF4F2   (输入框/次级卡/分段控件)
分隔线          bg.separator   rgba(33,34,40,0.08)
品牌渐变        brand.gradient  #9BDFAC → #5CD5C4 → #0CBDE6  (logo 中段→尾段；用于主按钮、进度条、Tab 指示器、聚焦光晕)
品牌主色        brand.primary   #0CBDE6   (天青蓝，交互高亮/链接/选中态)
品牌辅色        brand.fresh     #9BDFAC   (薄荷绿，成功态/在线徽章)
前景主文字      text.primary   #212228   (与 logo 字标同色，近黑不纯黑)
前景次文字      text.secondary rgba(33,34,40,0.55)
前景弱文字      text.tertiary  rgba(33,34,40,0.35)
语义色          红 #FF3B30（删/错）· 绿 #34C759（下载完成）· 橙 #FF9500（转码中）
海报占位        placeholder    #E8EFED   (骨架屏，配呼吸动效)
```

**深色（播放层/TV/夜间浏览）**

```
背景基底        #0B0C0F → 微调带青调 #0A0F11
表面一级        #15191C    表面二级  #1C2226
品牌主色        #22C8EE（天青蓝提亮一档，暗底可读）
文字            rgba(255,255,255,0.96 / 0.60 / 0.36)
```

**渐变使用纪律**（小清新不等于花哨）：渐变只出现在 4 个位置——①主"播放"按钮 ②进度条/Tab 指示器 ③TV 聚焦光晕 ④启动页 logo。其余一律纯色，保持克制。

**海报优先原则**：屏幕上 70% 面积属于海报/剧照。浅色模式下海报彩色块在近白底上天然突出，UI 铬件退为纯白卡 + 细分隔线，不与内容争抢；播放层内 OSD 用深色磨砂玻璃（rgba(11,12,15,0.72) + blur(24)）浮在画面上。

### 2.2 圆角与形状


### 2.3 字阶（衬线不用，全部无衬线；中文优先思源黑体/MiSans，西文 SF 风格系统字）

```
display    34 / w700   详情页片名
title      22 / w700   页面标题
headline   17 / w600   卡片标题
body       15 / w400   正文
caption    13 / w500   辅助信息
micro      11 / w600   徽章（HDR/4K/字幕）
```

### 2.4 动效（苹果语法的三条铁律）

1. **Hero 转场**：海报卡 → 详情页，海报无缝放大飞入（Flutter `Hero` + `flightShuttleBuilder`，400ms，曲线 `Cubic(0.2,0,0,1)`）
2. **SharedAxis**：同层级页面切换横向推入；跨层级（详情→播放）纵向淡入
3. **触达即反馈**：按压卡片缩放 0.97 + 阴影收紧，80ms；不做无意义的装饰动画

## 三、三端形态规格（AdaptiveShell）

统一入口：启动时按 `设备形态 + 短边断点` 选壳，运行期桌面窗口可拖动缩放自适应。

```
形态判定：
  桌面   = Windows / macOS / Linux 桌面
  手机   = Android/iOS 且 竖版为主（断点 < 600）
  TV     = Android Leanback / 无触控 + 大屏（≥ 960 且 dpad 存在）
```

### 3.1 桌面端（Windows 优先）——"Infuse for Mac"形态

```
┌────────┬──────────────────────────────────┐
│        │                                  │
│  侧栏   │        内容区（自适应栅格）          │
│  76px  │   首页：英雄横幅(轮播) + 横向行       │
│  图标   │   库：响应式海报网格 4→6→8 列        │
│  +徽标  │   详情：左海报右信息，背景沉浸墙       │
│        │                                  │
└────────┴──────────────────────────────────┘
```

- 侧栏：图标导航（首页/媒体库/搜索/直播/设置），激活项胶囊高亮；hover 显文字提示
- 顶栏融进内容区（无独立 title bar，用 `appWindow` 定制），窗口四角跟随系统圆角（Win11）
- 鼠标滚轮横向滚行；键盘 `←→↑↓` 在网格内移动、`Enter` 播放、`空格` 暂停
- 保留能力：**遥控配对（janus）、Together 同看、兑换码** 全部迁入新壳

### 3.2 安卓手机端（竖版）——"VidHub"形态

```
┌──────────────┐
│ 沉浸内容区     │  状态栏沉浸，海报出血到顶
│              │  首页：继续观看大卡(16:9)
│  海报流 2 列   │      + 最近添加 2 列竖版网格
│              │  详情：顶部海报墙 60% 高 + 圆角上拉卡
│              │  播放器：单击显隐 OSD
├──────────────┤
│ 首页 库 搜索 我 │  底部 Tab 4 枚，胶囊指示器
└──────────────┘
```

- 手势：详情页下拉关闭；播放器单击显隐、双击左右快退/快进 ±10s、垂直滑动亮度/音量
- 触控目标 ≥ 44dp；列表行高 72
- Android 端播放用 **Media3**（硬解、省电，不动 mpv）

### 3.3 安卓 TV 端——"Apple TV app"形态

```
┌──────────────────────────────┐
│ 首页  媒体库  搜索  设置          │  顶部横栏，聚焦时胶囊放大
├──────────────────────────────┤
│   英雄横幅（聚焦时背景同步剧照）    │
│   横向行：焦点卡放大 1.12          │
│   + 圆角 + 8px 抛光外发光         │
└──────────────────────────────┘
```

- 复用现有 FocusZone 机制，**视觉全部重绘**：去 Kodi 棱角，焦点 = 放大 + 圆角 + 光晕，不再画边框
- 屏幕软键盘 `tv_keyboard` 重绘为 iOS 式圆角按键网格
- 遥控器方向键 = 唯一输入，所有触控手势不可用 → 每页提供 D-pad 可达路径

## 四、页面级规格（实施提示词，按页拆解）

> 本节即"提示词"：每页给出布局、数据来源（复用现有 catalog/provider）、行为与验收点。实施时逐页对照。

### P01 首页（Home）
- **桌面/TV**：顶部**海报轮播（Hero Carousel）**——自动取自服务器"最近添加/推荐"的高分条目，全宽 16:9 背景剧照 + 磨砂信息层（片名/年份/评分/一句话简介 + 渐变"播放"胶囊钮），5s 自动切换、支持手动左右切换与悬停暂停；无焦点时静默，不抢内容。
- 轮播之下：横向行：继续观看 / 最近添加 / 最近集数 / 按库分类行（每行的标题即服务器库名，点击行标题直达该库）。
- **手机**：顶部保留**精简轮播**（高度 44%，上下圆角出血，手势左右滑动），下方"继续观看"横向大卡（16:9，圆角 16，带进度条）→ "最近添加" 2 列竖版海报网格，向下无限加载。
- 数据：复用 `home_page.dart` 的现有 provider + `recommendations.dart`，仅换视图。
- 验收：冷启动 ≤ 1.5s 出首屏海报；轮播切图无白屏跳变；滚动 60fps 无掉帧（DevTools 检查）。

### P02 媒体库（Library）——智能加载服务器自带库
- **智能发现，零配置**：登录 Emby/Jellyfin 后自动调用现有 `catalog_api.views()`（`/Users/{id}/Views`）拉取服务器上已建好的库（电影/剧集/收藏/直播…），**服务器怎么建库，App 就怎么长**——库的名称、排序、图标全部跟随服务器配置，不要求用户在 App 里重建任何结构。库列表变化（服务器端新建/改名/删库）在每次启动与下拉刷新时自动同步。
- 顶部库切换胶囊按服务器返回顺序排列，焦点态用品牌渐变描边；桌面端库过多时胶囊行横向滚动。
- **每库自适应视图**：电影库 → 竖版海报网格（2 列手机 → 4–8 列桌面）；剧集库 → 网格 + 集数徽章；收藏库 → 混排；直播库 → 台标圆角方卡行（接 P07）。
- 排序/筛选收进右上角"⋯"圆角弹层（不要 Kodi 的侧滑面板）；支持"未看/看过/收藏/评分"快捷过滤。
- 增量加载：首次进库分页拉取 + 滚动加载；图片走 `image_disk_cache.dart` 磁盘缓存。
- 验收：1 万级条目下网格滚动不卡；服务器端建一个新库，App 重启后自动出现且排序跟随服务器；库内筛选/排序状态可记忆。

### P03 详情页（Details）——沉浸式核心
- 背景层：30% 透明渐变叠加的剧照墙（自动取 backdrop，TV 聚焦时背景联动）。
- **桌面**：左海报（圆角 12）+ 右信息列：片名 display / 年份·时长·分级徽章 / 评分 / 剧情简介 / 演员横滚 / 季集切换胶囊。
- **手机**：顶部 55% 海报墙 → 信息卡以圆角 20 上拉覆盖，`DraggableScrollableSheet` 下滑可关。
- 主按钮：胶囊"播放 / 继续"（续播显示 S1E2 文案）+ 次级圆钮"已看/已收藏/下载"。
- Hero 动画：从任何海报卡进入均无缝放大。
- 验收：人物页/季集跳转全部可达；TMDB 中文元数据正常（zh-CN 已默认）。

### P04 播放器（Player OSD）——重写为 iOS 式
- 单击/轻触：显隐 OSD（顶部：返回 + 片名；底部：进度条 + 播放/暂停 + 音轨/字幕/设置）
- 进度条：内嵌 trickplay 缩略图气泡（复用 `trickplay.dart`），拖动实时跟手，松手 seek
- 右侧抽屉式设置面板（磨砂）：音轨 / 字幕（含样式延迟）/ 画质（转码档位）/ 倍速 / HDR 开关（走 DisplayGuard）
- 手机手势：双击左/右 ±10s；左侧竖滑亮度、右侧竖滑音量；下拉进度可关闭
- TV：D-pad 移动 + OK 确认，OSD 按钮 64×64 焦点块
- 验收：HDR 开启经 DisplayGuard 标记；断点续播准确；外挂字幕/音轨切换即时生效。

### P05 搜索
- **桌面**：`Ctrl+K` 全局唤起，居中磨砂大圆角搜索框，实时结果分"影片/剧集/人物"三段
- **手机**：搜索 Tab 页，顶部圆角输入框 + 历史胶囊
- **TV**：软键盘重绘 + 热门推荐词横滚
- 数据：现有 `search_page.dart` provider 原样复用。

### P06 设置
- 统一"iOS 设置列表"范式：分组圆角卡（16）+ 行内徽章 + 右箭头；二级页左滑推入。
- 分组：账号与服务器（Emby/Jellyfin 登录卡片化）/ 播放（HDR、音轨策略、字幕样式）/ 外观（语言已含中文）/ 网络（转码、代理）/ 关于（版本、日志、更新）。
- **"打开日志目录"保留**——闪退排查靠它。

### P07 直播（Live TV） / Together 同看 / 兑换码（Hub）
- 布局迁入新设计系统，功能逻辑零改动；直播频道列表换为圆角行 + 台标圆角方卡。
- Together 房间页：成员头像胶囊排 + 消息气泡（圆角 16，尾圆角 4）。

### P08 引导/登录（Onboarding / SignIn）
- 全屏剧照背景 + 磨砂居中卡片（圆角 20）逐服务器类型选择：Emby / Jellyfin 图标卡。
- 手机端单手可达（输入框在下半屏）。

## 五、实施里程碑（建议顺序）

### 8.2 质量体系增补（评审核心结论：测试网 M0 就建，不等到 M5）

- **Golden test 三态基线**（浅色/深色/播放深色）覆盖 theme2 基础组件，CI `flutter test` 卡点，golden 失败禁止合并。

### 8.3 工程修正（研发评审事实纠错）

1. **播放路由解耦**升为硬前置 M0.5（mpv_backend.dart:96-98 / media3_backend.dart:87-89 内部 push OSD 路由，重写 OSD 必动）。
2. **UI 规模修正**：77 文件 / 约 1.8 万行（原估 1.1 万低估 6 成），player_osd.dart 单文件 1546 行——M2/M5 工作量按实际基数重估。
