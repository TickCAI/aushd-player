# AusHD Player v0.1 测试版交付说明

> 本文写给拿到 **v0.1 测试版** 安装包的你，以及帮你试用的朋友。
> 适用分支：`ui-redesign`；产物由 GitHub Actions 手动触发构建，发布到 GitHub Releases。
> 一句话：**这是并行试用的测试版，不是 v1.0.1 的升级包；不推自动更新，随时可以退回稳定版。**
> **状态说明**：本文按当前分支实况编写。v0.1 新界面的 4 个 tab（首页 / 媒体库 / 搜索 / 设置）已从 M1 占位骨架替换为 **M2 真实页面**，并完成 **M3 手机竖版**与 **M4 安卓 TV D-pad** 适配；详情 / 剧集 / 合集等二级页仍按路由回落走经典实现（已包深色主题，视觉不一致但功能完整）。凡标注「仍走经典实现」的页面由「更多」tab 与 `AUSHD_LEGACY_UI` 回落机制兜底，不会丢功能。

## 一、版本与渠道

| 项目 | 说明 |
| --- | --- |
| 版本号 | **v0.1**（测试版序列 `0.1 → 0.2 → …`，不走 v1.9 / v2.0.0 命名） |
| 渠道 | **beta**（构建时注入 `--dart-define=AUSHD_CHANNEL=beta`；稳定版为 `stable`） |
| 自动更新 | **不推送**。测试包把 `AUSHD_DIST_URL` / `AUSHD_HUB_URL` 注入为空，自建更新器、hub、日志上传全部静默关闭 |

| 与 v1.0.1 的关系 | **v1.0.1 仍是稳定版，已冻结为 fallback**。测试版是独立并行的试用序列，不是它的升级；等新界面稳定后再议正式版本号 |
| Release 标题 | `AusHD Player v0.1 测试版`（带「测试版」后缀，便于和稳定版区分） |

### 回退路径

1. **临时回退到旧界面（不用卸载）**：① 新壳桌面侧栏底部有「**经典界面**」按钮，点它即可打开旧完整壳；② 或用 `--dart-define=AUSHD_LEGACY_UI=true` 构建的包，整个 home 切回经典 `Shell`（含全部 13 个 `ShellTab`，与 v1.0.1 完全一致；`lib/main.dart` 的 `ZerkApp.legacyUi` 已实现，默认 false 走 `AdaptiveShell`）。两者都用于对比归因，方便判断问题出在新界面还是底层。
2. **彻底回到稳定版**：卸载测试版后，重装 **v1.0.1 安装包**（Windows `setup.exe` / Linux `tar.gz` / Android TV `APK`）。v1.0.1 的数据与登录态保留，重装即可继续用。
3. **Android 覆盖安装**：`pubspec.yaml` 刻意保持单调递增的 `versionCode`，测试版可以直接覆盖安装到 v1.0.1 之上；但**跨序列回退建议先卸载再装**，避免版本序列混乱。

> 测试版与稳定版可以并存观察：桌面端装到不同目录即可；Android 若覆盖安装，注意回退时按第 2 条处理。

## 三、如何在 GitHub Actions 手动触发测试版发版

> 当前 `build.yml` 的 tag 推送（`push: tags: ['v*']`）会强制要求 `DIST_URL` secret，而分发后端尚未部署，因此**不要用推 tag 的方式发测试版**，改用下面的手动触发。

1. 打开仓库页面，点顶部 **Actions** 标签。
2. 在左侧工作流列表里选 **Build AusHD Player**。
3. 点右侧的 **Run workflow** 下拉按钮。
4. **Use workflow from**：分支选 **`ui-redesign`**。
5. 填写表单：

   | 字段 | 填什么 | 为什么 |
   | --- | --- | --- |
   | `tag` | **`v0.1`** | 测试版号，产物文件名与 Release 标题都取它；不要填 `v1.0.1` |
   | `skip_distribution` | **勾 `true`**（保持默认） | 纯构建模式，不需要 `DIST_URL`，更新器/hub 静默关闭 |
   | `test_release` | **勾 `true`** | 用 v0.1 测试版号构建并发布 Release，**跳过 DIST_URL 检查** |

6. 点绿色 **Run workflow** 按钮启动。
7. 等 `preflight` → 三个 `build`（windows / linux / androidtv）全绿后，`release` 作业自动创建 GitHub Release，标题为 **AusHD Player v0.1 测试版**，并附上三个安装包。
8. 到仓库 **Releases** 页，按自己平台下载安装包。

**这一组勾选实际做了什么**

- `TEST_MODE=true`、`BUILD_CHANNEL=beta`：三端构建统一注入 `AUSHD_CHANNEL=beta`。
- `REQUIRE_DIST` 强制为 `false`：跳过 `DIST_URL` 校验，无需配置任何 Secret。
- Release 标题追加「测试版」后缀，`generate_release_notes` 自动生成更新说明。
- 「Register artifacts with distribution service」步骤被跳过：不向不存在的分发后端注册版本。

**现有 tag 发版逻辑没有改动**：推送 `v*` tag 仍走完整发布流程（`DIST_URL` 必填、注入分发地址、登记版本、渠道 `stable`）。测试版是新增的独立触发方式，两者互不影响。

## 四、页面迁移清单（CineIsle 式路由回落）

**策略（最重要的一句）**：新界面采用**渐进式替换**——新壳 `AdaptiveShell` + 新路由表 `z_routes.dart`：**路由表里已登记新实现的 tab 走新页面，未登记的 tab 自动回落到 v1.0.1 的经典实现**。具体保证：

- 新 UI 一页一页长出来，**随时可以发版**；
- **永不出现空页面、功能不会丢**：`ZRoutes.fallback()` 会显式给经典页面包一层深色 `buildTheme()`，避免新壳的浅色主题让旧页面白底白字；
- 回落覆盖两类情形：① 新路由表**未登记**的 tab（当前仅 `more`）直接回落到**完整的经典 Shell**，v1.0.1 的全部页面与功能从这里继续可达；② `--dart-define=AUSHD_LEGACY_UI=true` 时整个 home 切回旧 `Shell`（含全部 13 个 `ShellTab`，与 v1.0.1 完全一致）；
- 桌面侧栏（Rail）底部还有「**经典界面**」按钮，随时一键打开旧完整壳；
- 默认 `AUSHD_LEGACY_UI=false` 走 `AdaptiveShell`，该开关由 `lib/main.dart` 的 `ZerkApp.legacyUi` 实现，用于整体对比归因。

### 新壳的 5 个顶层 tab

| Tab | 新界面（M2 真实页面） | 回落（经典实现） |
| --- | --- | --- |
| 首页 | `ZHomePage`：Hero 海报轮播（7s 自动切换、可关）、继续观看（横卡 + 进度 + 剩余时长）、最近添加电影 / 剧集、媒体库快捷入口 | `HomePage`（`home_page.dart`） |
| 媒体库 | `ZLibraryPage`：服务端 `Views` 库分类胶囊、最近添加/名称/评分/年份四种排序、滚动增量加载、下拉刷新 | `LibraryPage`（`library_page.dart`） |
| 搜索 | `ZSearchPage`：350ms 防抖实时搜索（电影/剧集/合集）、海报网格 | `SearchPage`（`search_page.dart`） |
| 设置 | `ZSettingsPage`：账户卡片（服务器 / 类型 / 退出登录）、外观说明、**导出诊断包**、经典界面入口 | `SettingsPage`（`settings_page.dart`） |

| 限制 | 现状与建议 |
| --- | --- |
| **golden 基线待补** | 浅色 / 深色 / 播放深三态参考图尚未生成，`quality.yml` 暂未接 golden 门禁（现有硬门禁为 `flutter test` + `flutter build apk --debug`）。本轮已在本地装好 Flutter 3.50，基线可以开始产出，作为下一个质量项处理 |

| **TV 焦点寻路依赖几何** | 新页面用既有 `ZoneNavigator` 做方向键几何寻路；极端布局（卡片宽度差异过大）下可能需要在同一行里多按一次方向键，属已知体验细节，后续接 N 卡焦点记忆 |
| **Android TV 打不开日志目录** | `AppLog.openFolder()` 在 Android 是空操作（`LogSink.reveal()` 仅处理 Windows 的 `explorer.exe` 与 Linux 的 `xdg-open`）；Android TV 用户需用文件管理器自行定位应用日志目录 |
| **TMDB key 内置** | `lib/app/release.dart` 内置默认 TMDB API Key，保证元数据开箱可用；可在设置里覆盖，或用 `--dart-define=AUSHD_TMDB_KEY=...` 在构建时替换。该 key 有调用配额，**对外公开分发前建议换成自己的** |
| **HDR 排障建议** | 播放 HDR 时默认自动开启 Windows HDR（可在 设置 → 播放器 关闭「HDR 自动开启」）。若崩溃后桌面持续发灰发白（HDR 状态跨重启持久）：① 重新打开 AusHD Player，启动时会自动检测并关闭上次异常退出遗留的 HDR；② 手动到 设置 → 系统 → 屏幕 关闭「使用 HDR」；若仍发灰，检查 设置 → 辅助功能 → 颜色滤镜 是否被开启。DisplayGuard 不动，重开 OSD 后仍会跑 `player_smoke` 冒烟 |

## 六、朋友闪退了怎么办

> **当前可用入口**：默认新界面下，打开左侧「**设置**」tab，页面里直接就有「**导出诊断包**」与「**打开日志目录**」两个按钮（`ZSettingsPage` 已接入 `DiagnosticsButton`）——该页既没有「诊断」分区，也没有「关于」分区，不用到处找。
> **经典界面**（`AUSHD_LEGACY_UI=true` 构建包，或新壳「更多」tab 回落的旧 `Shell`）则是「**设置 → 诊断 → 打开日志目录**」，**只有打开目录、没有导出按钮**，同样没有「关于」分区。想一步导出请用默认新界面的「设置」tab。

请朋友按下面做，把文件发回来即可定位（**诊断包是纯文本，不含账号、密钥、设置等敏感内容**）：

1. **先重开一次 App**：崩溃后启动时会自动清理上次遗留的 HDR 状态，桌面发灰问题多半能立刻恢复。
2. 打开 **设置**（新界面默认左侧「设置」tab；经典界面为 设置 → 诊断）。
3. 点 **「导出诊断包」**：一键生成 `aushd-diagnostics-<yyyyMMdd-HHmmss>.txt`（单文件纯文本、UTF-8、无 zip / 无加密、可直接微信发送；示例 `aushd-diagnostics-20261113-015700.txt`），落到日志同目录（`<应用支持目录>/logs/`）。内容 8 段：版本、平台、时间、系统信息、最近 400 行日志、DisplayGuard 标记（**只报有无、不导内容**）、`[error]` 崩溃条目（最多 50 条）、启动次数与脱敏说明（**不读取任何设置值、密钥、账号**）。导出失败只提示「导出失败，请重试」，异常不会抛到界面。
4. 或点 **「打开日志目录」**：Windows 用资源管理器、Linux 用文件管理器打开日志目录（版本号 / `AppLog.file` 完整路径就在附近）；**Android TV 上此按钮无效**（`LogSink.reveal()` 只处理 Windows / Linux），需自行用文件管理器找到应用日志目录。
5. 把那个 **`.txt`**（或目录里最新的日志文件）通过微信等发回来；没有应用内分享面板 / 微信 SDK，需手动挑文件。
6. 顺带说一句闪退前在做什么：播放哪部片、是否开了 HDR、停在哪个页面、能否稳定复现。

> 小圈子没有崩溃上报后端（分发后端未部署），这个 `.txt` / 日志文件就是唯一的质量回路，麻烦一定带上。
